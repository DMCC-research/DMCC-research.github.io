从 7 月 27 日到 8 月 2 日，数据搬移领域最清晰的信号是：长上下文和智能体推理服务正在让调度器感知内存对象。KV 页面、远程缓存层、PIM 操作数、检索记录和沙箱产物不再只是实现细节；它们正成为具有放置、保留、传输和成本策略的对象。

## KV 缓存 | 页面需要元数据，而不只是容量

[LOCKS](https://arxiv.org/abs/2607.24555) 将长上下文解码视为页面选择问题：它为每个页面构建紧凑的键摘要，根据这些摘要估算注意力权重总量，并选择性地读取 KV 页面，而不是扫描整个缓存。对基础设施的启示很直接：KV 页面需要摘要和准入决策，而不只是分配槽位。

[DualDecoder](https://arxiv.org/abs/2607.26475) 采用了互补的路径。它利用辅助解码状态预测未来的 KV 需求，并使主机到 GPU 的 KV 搬移与计算重叠进行。如果说 LOCKS 关注哪些页面可以跳过，那么 DualDecoder 关注的就是哪些页面应在进入关键路径之前搬移。

[DynaCalKV](https://arxiv.org/abs/2607.24331) 通过注意力头分组和自适应秩分配来压缩 KV 缓存，并分别处理键和值，从而提供了另一种调控手段。这使压缩元数据与驻留元数据一起，成为推理服务约定的一部分。

[稀疏性的上限](https://arxiv.org/abs/2607.26648) 提出了警示：只要内存加载仍然发生，活动稀疏性就不能保证节能。[从 Token 到瓦时](https://arxiv.org/abs/2607.26571) 通过在推理能耗模型中显式纳入注意力读取、参数访问、预填充和解码等组成部分，进一步强化了这一方向。共同的启示是：只有消除高成本内存流量，或掩盖其开销，稀疏化和压缩才有意义。

我的解读是：KV 缓存正在演变为一个上层提供张量 API 的存储层次体系。研究议程不应再只问能容纳多少 KV，而应开始追问：在推理服务期间，对 KV 进行路由、压缩、预取、淘汰和审计需要哪些元数据。

## 内存分层 | CXL 和 PNM 需要感知工作负载的放置策略

[NELSSA](https://arxiv.org/abs/2607.26633) 提出异构 GPU-PNM LLM 推理服务，采用基于长度的请求放置、运行时上下文迁移、在近内存处理单元上执行的稀疏注意力，以及 CXL/RDMA 式的跨层搬移。它的重要主张不只是 PNM 能帮助 LLM 推理服务，而是请求长度会改变上下文应驻留的位置，以及应由哪条计算路径处理。

[一种光子 CXL 内存设备](https://arxiv.org/abs/2607.27187) 提出利用光子 CXL 内存设备构建共享 KV 缓存层，其动因是电互连 CXL 的扩展限制，以及 KV 淘汰对首个 token 生成时间的影响。这推动 KV 缓存从各 GPU 上残留的数据，转变为池化的推理服务基础设施。

[LLMET](https://arxiv.org/abs/2607.26491) 评估了新兴 M3D 内存在 LLM 推理服务中的表现，重点关注片外数据搬移能耗、大容量片上缓存的影响以及跨层仿真。这让关注点始终落在实际瓶颈上：新的内存基底能否减少工作负载中占主导地位的推理服务阶段所产生的高成本流量。

尚待解决的问题是资源争用下的 QoS。只有当命中率、延迟、带宽和调度开销的综合表现优于本地淘汰或重新计算时，远程或池化 KV 层才有用。“更多内存”并不等于“更少的关键路径搬移”。

## 近数据计算 | 边界成本决定收益

[PIMID](https://arxiv.org/abs/2607.24196) 的价值在于，它将存内计算建模为一个全系统问题，涵盖主机与设备之间的边界开销、处理单元在内存层次中的放置、执行模型差异，以及对内存基底的敏感性。这才是评估近数据计算的恰当方式：每减少一个字节的搬移，都必须与同步、编排和布局成本相权衡。

[超越预填充与解码分离](https://arxiv.org/abs/2607.25498) 将放置问题从固定推理服务阶段拓展到异构平台上的动态算子调度，包括 NPU/PIM 放置、阶段感知 DAG、闭环放置和分块权重布局。这一点很重要，因为不同阶段会呈现不同的主导数据对象：权重、KV、激活值和中间数据块需要的放置策略并不相同。

[NELSSA](https://arxiv.org/abs/2607.26633) 将这种近数据视角应用于稀疏注意力和混合长度的解码服务。共同的方向是根据每个有效 token 所需搬移的字节数来放置算子，而不只是看加速器利用率。

## 检索 | 智能体记忆开始呈现存储引擎的形态

[MemLens](https://arxiv.org/abs/2607.25992) 提出面向 LLM 智能体的价值感知记忆管理，将记忆记录视为数据对象，对其进行 Shapley 式估值、生命周期分析和价值感知保留。这使智能体记忆从便捷的向量搜索功能转变为保留与成本管理层。

[主动 RAG 应何时检索？](https://arxiv.org/abs/2607.24010) 在效用、校准和成本约束下评估检索触发机制。从数据搬移的角度看，这意味着只有当预期效用足以证明检索计算、索引访问和 token 预算的支出合理时，证据才应进入上下文。

[Agent-UCT](https://arxiv.org/abs/2607.24162) 引入了成本感知的工作流搜索，采用物化的工作流前缀和内容可寻址缓存。[CACD](https://arxiv.org/abs/2607.24332) 则通过交叉注意力校准的去重和分块冗余削减，实现检索索引压缩。这些论文共同指向这样的检索系统：能够显式呈现缓存命中、冗余字节、返回记录、注入的 token，以及实际的证据使用情况。

几篇范围更聚焦的论文也符合这一模式：[一种图原生双时态记忆存储](https://arxiv.org/abs/2607.26520) 引入不可变的记忆标识和时间点检索；[HYSET](https://arxiv.org/abs/2607.25718) 将工具检索视为基于共同调用结构的集合级选择；[APS-RAG](https://arxiv.org/abs/2607.24663)、[TCellAlign](https://arxiv.org/abs/2607.24093) 和[历史文档图检索](https://arxiv.org/abs/2607.24475) 展示了特定领域的检索工作流，其中溯源和证据搬移塑造了系统。

有用的抽象不是“top-k 检索”，而是面向智能体记忆的存储引擎：保留、压缩整理、时态语义、缓存准入和检索成本核算。

## 智能体运行时 | 调度范围超越 Token

[SpecBox](https://arxiv.org/abs/2607.23933) 提出面向 LLM 智能体推理服务的推测式沙箱调度，涵盖意图驱动的预分配、沙箱依赖图、语义结果缓存、共享内存传输，以及尾延迟与内存之间的权衡。这将数据搬移的范围扩展到了模型张量之外。

正如 [SpecBox](https://arxiv.org/abs/2607.23933) 所指出的，对智能体系统而言，成本高昂的对象可能是沙箱、依赖树、缓存的工具输出、文件系统产物和 IPC 载荷。只关注 GPU 批次的调度器会忽略这些内存和延迟压力。只关注相关性分数的检索系统会忽略将证据搬入上下文的成本。只关注算子局部性的近数据放置策略会忽略其与请求长度及缓存驻留状态的相互作用。

## 结论

生产实践的方向是状态感知的推理服务：KV 页面、检索记录、工具集合、工作流前缀、远程内存和沙箱产物都需要明确的放置和生命周期策略。研究方向则是建立一个通用成本模型，能够跨内存层级和智能体运行时，比较摘要生成、压缩、预取、迁移、保留和重新计算的成本。
