8月31日–9月6日的研究窗口将三项推理服务决策联系起来：读取哪些缓存上下文、何时加载模型参数，以及何时可以提交智能体的推测性工作。架构上的机会在于明确状态的生命周期与访问方式，同时分别衡量每种机制的成本。[VestigeKV](https://arxiv.org/abs/2609.03949v1)、[延迟感知编排](https://arxiv.org/abs/2609.03335v1)、[推测性宏提交](https://arxiv.org/abs/2609.03236v1)

本期更新涵盖所提供的、关于该时间窗口内发表论文的证据，采用链接中的 arXiv v1 版本。文中报告的结果均为作者声称的结果；相关基准测试尚未经独立复现。

VestigeKV 对**保留上下文与常规地对其执行注意力计算**作出了有用的区分。它从 NoPE-MLA 缓存中提取与查询无关的选择信号，对一个子集执行注意力计算，并将被排除的行保留在 GPU 上的精确归档中，以便按条件召回。卸载到主机是一个单独的变体。这对基础设施的直接启示比“更小的 KV 缓存”更为有限：减少常规注意力访问量，仍可能让归档状态驻留在 GPU 上。[VestigeKV](https://arxiv.org/abs/2609.03949v1)

声明式注意力通过模型与运行时之间的接口实现选择性访问。模型发出全局、聚焦或局部注意力指令，运行时将这些指令转化为受限的 KV 访问。作者报告称，参与注意力计算的 token 数量减少，同时准确率有所下降。VestigeKV 从缓存结构中推导选择结果，而声明式注意力则显式给出由模型生成的访问范围；所提供的证据并未确定非活跃状态应存放在哪里，也未确定参与注意力计算的 token 数量减少是否会按比例转化为延迟降低。[语言模型可以控制自身的注意力](https://arxiv.org/abs/2609.02737v1)

对话缓存引入了另一项决策：可复用状态是否保留到下一轮。多轮 LRU 论文针对不断增长的对话历史，推导了极限命中率及其估计器。论文描述的推理服务模型将可复用历史保留在预填充器的 HBM 中，将 KV 传输到独立的解码器，并返回响应 token，但不返回响应 KV。因此，下一轮仍需为上一轮响应构建 KV。前缀缓存命中并不能消除后续所有的构建或传输成本。[LRU 下的多轮 LLM 对话](https://arxiv.org/abs/2609.02027v1)

**我的研究重点是衡量：当注意力变为选择性访问时，哪些字节实际上不再占用或传输。** 这三篇论文促使我们考虑开展对话级追踪，将驻留容量、实际注意力读取、归档恢复、重新计算以及预填充器到解码器的传输区分开来。这种区分将揭示一项优化究竟是为更多请求腾出了容量、降低了带宽需求，还是将工作转移到了偶发的恢复事件中。仅凭参与注意力计算的 token 数量，无法区分这些情况。这是根据相关机制提出的评估方案，而非已经得到验证的综合结果。[VestigeKV](https://arxiv.org/abs/2609.03949v1)、[声明式注意力](https://arxiv.org/abs/2609.02737v1)、[多轮 LRU](https://arxiv.org/abs/2609.02027v1)

并行生成带来了一个相关的成本核算问题。Uno 将自回归主干网络与轻量级扩散参数及一个采样器结合起来，作者声称该采样器能够保持自回归分布，且无需独立的草稿模型。Free Pause Tokens 使用共享权重的并行预测流，在不增加序列长度或持久 KV 状态的情况下增加计算量。Uno 的作者报告了在所评估的各批量大小下的吞吐量提升；这些结果并不能证明每种硬件或工作负载配置都能获得同样的收益。[Uno](https://arxiv.org/abs/2609.04010v1)、[Free Pause Tokens](https://arxiv.org/abs/2609.03807v1)

值得检验的假设是：这些额外计算能否足够高效地复用已读取的权重和上下文，从而使临时缓冲区与同步的开销物有所值。仅有权重共享并不能证明发生了物理层面的复用，而持久 KV 不变也不能证明峰值内存占用不变。为评估其对边缘设备的适用性，实验应在不同批量大小和上下文长度下纳入持续功耗与设备内存限制；这些来源并未证明其具有 NPU 部署优势。[Uno](https://arxiv.org/abs/2609.04010v1)、[Free Pause Tokens](https://arxiv.org/abs/2609.03807v1)

在工作流层面，延迟感知编排将参数加载纳入调度。它利用预测的执行时间、内存需求和模型加载成本构建物理执行备选方案，联合选择融合、生命周期操作、放置位置及执行顺序。作者报告称，在其评估的异构 GPU 工作负载上，总完工时间、p95 完成延迟和 GPU 秒数均有所改善。[延迟感知编排](https://arxiv.org/abs/2609.03335v1)

这在架构上的启示是，工作流依赖关系可以提前提供参数需求信息。调度器可以利用这些信息提前加载模型、保留模型，或释放其内存。这些选择需要分别归因：预取可能掩盖加载时间，但传输量保持不变；更早驱逐则可能减少空闲占用，却导致后续再次加载。一个有价值的后续研究方向是，在存在预测误差和突发请求到达的情况下，区分避免的加载、与其他工作重叠的加载，以及减少的排队时间。[延迟感知编排](https://arxiv.org/abs/2609.03335v1)

推测性宏提交将调度扩展到试探性执行。它在隔离快照上运行预测的动作链，并在权威执行主体的下一步动作与草稿匹配时，复用多个已执行步骤。其报告的 AppWorld 延迟改善伴随着任务完成方面的权衡，因此，每个成功任务的成本成为衡量耗时之外不可缺少的配套指标。[推测性宏提交](https://arxiv.org/abs/2609.03236v1)

Git4Data 提供了一种互补的状态管理机制：基于不可变对象存储和多版本并发控制，实现数据库分支、差异比较与合并，并声称版本操作成本随变更量而扩展。它尚未被验证可作为推测性宏提交的后端。我的理解是，二者的结合值得开展提交语义研究：低成本分支只有在运行时也核算分支执行、冲突、被丢弃的工作，以及产生已接受观测结果的状态的安装成本时，才有价值。仅在第一个动作上达成一致，并不能证明后续每个动作都有效。[Git4Data](https://arxiv.org/abs/2609.02106v1)、[推测性宏提交](https://arxiv.org/abs/2609.03236v1)

衡量范围应延伸至智能体任务的其余部分。Bioinfoysis 描述了持久化的分析运行和绑定版本的交接；DNative-Twin 强调捕获的工具状态与重放契约。CAE 测试框架研究在信息与修复预算匹配的条件下考察执行反馈和教程上下文，而 READY 则根据可靠性与成本约束选择监督策略。这些研究共同促使我们在报告每个成功完成任务的成本时，追踪产物传输、重复摄入上下文、修复、验证与审查。它们尚未量化共同推理服务栈的优势。[Bioinfoysis](https://arxiv.org/abs/2609.03871v1)、[DNative-Twin](https://arxiv.org/abs/2609.03787v1)、[CAE 测试框架研究](https://arxiv.org/abs/2609.03718v1)、[READY](https://arxiv.org/abs/2609.02095v1)

下一步研究是开展运行时追踪，为 KV、参数、产物和推测性分支明确生命周期、迁移成本与有效性规则。从选择性 KV 访问入手，再将模型加载决策和推测性提交接入同一套任务级成本核算。本周的机制为这项研究提供了依据；它们尚不足以支持芯片推荐，也未证明可量化的数据中心 TCO 收益。[VestigeKV](https://arxiv.org/abs/2609.03949v1)、[延迟感知编排](https://arxiv.org/abs/2609.03335v1)、[推测性宏提交](https://arxiv.org/abs/2609.03236v1)、[READY](https://arxiv.org/abs/2609.02095v1)
