在 2026 年 7 月 6—12 日这一周，数据移动方面最强烈的信号是：上下文和推理服务状态越来越少被视为不透明的模型内部要素，而更多被视为需要明确安排存放位置的系统数据。本周的论文涉及 SSD 支撑的语义记忆、压缩 KV 归档、推理服务的字节量下限分析、SQL 内部的 AI 函数以及分区式边缘推理，这些相互关联的尝试都旨在控制数据存放的位置及其经过的路径。

## KV 内存 | SSD 语义记忆与分形归档

[TF-Engram](https://arxiv.org/abs/2607.07388) 为大语言模型提出了一条由 SSD 支撑的记忆访问路径，在 GPU、DRAM 和 SSD 层级之间采用短语专属语义记忆、提前退出引导的预测性预取，以及隐藏状态注入。其数据移动机制很直接：将一部分长期存续的语义状态移出稀缺的加速器内存，再尝试通过预测掩盖访问较冷存储层的开销。

[分形 KV 缓存归档](https://arxiv.org/abs/2607.07144) 从另一个角度处理一个相近的问题，提出了一种面向长上下文 KV 状态的符号化存储表示，采用收缩迭代映射编码、原位检索和 O(1) 随机访问，并关注键值量化的不对称性。TF-Engram 将外部语义记忆检索到模型处理路径中，而分形 KV 探讨的是：类似 KV 的状态能否在保持实用随机访问能力的同时，继续以压缩归档形式存放。

这对基础设施的启示并不只是“添加 SSD”或“压缩 KV”。两种设计都是用一种移动模式换取另一种。只有当预取未命中、排队和隐藏状态注入的开销不超出延迟预算时，SSD 支撑的记忆才能减轻加速器上的驻留压力。只有当重建、元数据访问和质量敏感性不成为新的瓶颈时，KV 归档才能减少驻留字节量。我的判断是，最有用的后续工作是建立一份数据移动账本：HBM 中减少了多少字节，经由 SSD 或 DRAM 增加了多少字节，引入了多少重建工作，以及并发推理服务下面临多大的尾延迟风险。

## 推理服务 | 调优前先理清字节量下限的先后次序

[网格搜索之前先思考](https://arxiv.org/abs/2607.05876) 是本周最清晰的系统层面信号，因为它聚焦于 LLM 推理服务中各类资源瓶颈出现的先后次序。该论文围绕 HBM 字节量、网络字节量、网络消息数、KV 容量以及重叠后残留的开销来组织推理服务分析，并给出了涉及 GPU 推理服务、MoE 和 MLA 式推理的示例。

这种分析框架很重要，因为在明确主导的数据移动路径之前，许多推理服务方案看起来并无差别。HBM 容量决定 KV 能否留在本地。HBM 带宽影响解码吞吐量。网络字节量和网络消息数决定并行化是否会带来代价高昂的激活、专家或 KV 流量。重叠后残留的开销则决定了那些在调度中看似被隐藏的数据移动，在实际执行时是否真的被隐藏。

对于生产系统，这意味着应当先核算资源下限，再开展大范围的配置搜索。网格搜索仍然可以用于调优，但当真正的约束是字节传输路径或消息传输路径时，它不应成为首选工具。

## 数据系统 | AI 函数让计算靠近受治理的数据

[Spider 2.0-AIFunc](https://arxiv.org/abs/2607.06229) 将文本到 SQL 的评估扩展到 AI 原生 SQL 工作流，涵盖 SQL 内部的 AI 函数、执行稳定的基准测试、谓词落地、模式落地，以及靠近数据库的模型使用。尽管它以基准测试的形式呈现，但这仍然是一个数据移动问题：一旦由模型介入的操作进入 SQL 执行计划，系统就必须决定，是将数据行移动到模型服务，将模型执行移向数据仓库，还是移动紧凑的谓词、嵌入和中间摘要。

这对研究的启示是，AI 原生查询规划需要针对 token 载荷、数据行物化、模型延迟、数据出站边界以及以模式为依据的检索建立成本模型。仅凭准确率，无法解释这些工作流在架构上是否可行。

## 边缘计算 | 分区的关键在于什么穿过链路

[Voltron](https://arxiv.org/abs/2607.07046) 面向边缘智能中的弹性多设备 LLM 推理，涵盖协同执行、设备弹性以及延迟与隐私之间的权衡。R2 问题是，实际穿过薄弱链路的究竟是什么：参数、激活、KV 状态、私有输入数据，还是中间摘要。

值得关注的机制是在互连条件变化时如何放置分区。如果激活传输占据主导、KV 状态必须反复跨设备传输，或者隐私约束阻止了最节省带宽的放置方案，那么即使某种切分方式节省了本地计算，也仍然可能失败。

## 检索 | 较小的状态仍可能是关键状态

两篇较轻量的论文在应用层呈现了同样的模式。[观察与反思](https://arxiv.org/abs/2607.07108) 将双轨记忆、持久多模态记忆、嵌入记忆和倒数排名融合用于推荐。这里的数据移动问题是：每次交互需要检索多少用户、媒体和协同状态，延迟和过时的偏好状态才会开始占据主导。

[关于 API 调用的 RAG 论文](https://arxiv.org/abs/2607.05936) 将 OpenAPI 端点检索、基于规范的生成、正则表达式约束解码和检索增强生成结合起来，用于 Web API 调用。这里的载荷虽小，却在结构上十分重要：将正确的端点规范和约束引入解码过程，可以减少无效输出和下游纠错工作。

## 经济背景 | 将内存稀缺视为情景，而非证明

[内存稀缺、开放模型与 AI 行业重构](https://arxiv.org/abs/2607.07207) 围绕每拍字节的美元成本、受带宽限制的解码、DRAM/HBM 稀缺以及较早代际内存的所有权来分析推理经济性。我会将其用于构建情景框架，而不是作为具体市场预测的证据。它对本周主题的有益贡献在于提醒我们：推理服务的经济性越来越多地以每美元和每瓦所能交付的字节量来衡量，而不只是加速器的 FLOPs。

## 方向

生产方向很明确：AI 基础设施需要对上下文驻留、存储层级间迁移、重建工作和通信下限进行明确核算。研究方向同样具体：根据各种记忆机制避免了哪些移动、引入了哪些移动，以及带来了多大的延迟方差来比较它们。
